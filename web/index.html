Ownership you never have to annotate.

Science is a compiled language for scientific computing and machine learning, written for people who arrive from NumPy and PyTorch and have never written a lifetime annotation. It keeps what ownership buys — no garbage collector, and memory released at a program point the compiler can name — and refuses the notation that normally pays for it: the programmer never writes a region, and the compiler infers them across function boundaries. Blocks are indentation, keywords are English words, and C libraries are called directly, because every floating-point routine worth using is already written in C. 

$ sciencec build hello.science
$ ./hello
hello, world
$ echo $?
0
What actually works Read the program

hello.science is one line, print("hello, world"), and that transcript is the compiler's own gate test rather than a mock-up: it is hello_world_runs_and_exits_zero in crates/science-codegen-llvm/tests/hello.rs, which builds the program, links it, runs it, and asserts both the bytes and the exit status. Building sciencec with its backend needs a Rust toolchain and an LLVM 18.1 installation; without one, build stops at SC0400 and says exactly why.

Why it exists

Three refusals, each with the thing it is refusing for. None of them is free, and the prices are in the rationale rather than hidden.

Catch it before the run

Julia has the REPL and the ecosystem and cannot check a shape, a unit or a reused random key before running. Mojo has ownership and GPUs and no shapes in its types. JAX has the right transformation model and no static types. Science aims at the combination; the phase that exists today is the ownership half of it, and the typed-shape half is specified and not built.

Without asking for annotations

A scientist who has to learn 'a before writing a derivative will write the derivative in Python instead. So regions are an analysis result rather than a declaration: there are no elision rules, because elision is a syntactic guess made before the body is read, and the compiler reads the body anyway.

Without leaving the C ecosystem

dgemm is thirty years of hand-written assembly per microarchitecture. A language that cannot call it is not a scientific language, whatever its type system can prove, so the C boundary is a declaration in the language rather than a generated wrapper layer.

The claim, and the program that carries it

Two borrows go into denser and one comes back out. Which one it is depends on the values, so the compiler has to prove the returned borrow outlives the call. In Rust that proof is spelled <'a> three times in the signature. Here it is nowhere, and the guarantee is the same. 

type Sample:
    kelvin: F64
    grams: F64

# Two borrows go in and one comes back. Which one depends on the values, so
# the compiler has to prove the answer outlives the call. That proof is the
# whole of what a lifetime annotation would have told it.
def denser(a: &Sample, b: &Sample) -> &Sample:
    if a.grams >= b.grams:
        a
    else:
        b

let core be Sample(kelvin: 5778.0, grams: 12.5)
let shell be Sample(kelvin: 4100.0, grams: 3.25)

# `denser` declares its parameters `&`, so the call site is bare.
let winner be denser(core, shell)
print(f"{winner.kelvin} K at {winner.grams} g")   # => 5778.0 K at 12.5 g

Checked and built with sciencec check density.science and sciencec build density.science; the trailing comment is what the linked binary printed. The call site is denser(core, shell) and not denser(&core, &shell) because a parameter declared &T is borrowed automatically at the call site — Rust rejected that, Mojo adopted it, and for this audience Mojo is right.

The checking is real, which is the only way the claim means anything

Inference without enforcement is a language that compiles everything. Overlap a shared borrow with an exclusive one and the same compiler that asked for no annotations refuses the program, points at all three lines that make the conflict, and names the two fixes. 

error[SC0330]: `core` is borrowed here and borrowed exclusively before the borrow ends
  --> overlap.science:10:1
   |
 9 | let view be &core
   |             ----- `core` is borrowed here, shared
10 | warm(core)
   | ^^^^^^^^^^ ...and borrowed here, exclusively
11 | print(f"{view.kelvin}")
   |       ---------------- the first borrow is still needed here
   |
   = note: a shared borrow and an exclusive one cannot overlap (§6.1 rule 4)
   = note: the borrow ends at its last use, so moving the last use above the conflicting line is enough; binding what is needed before it is the other fix

Verbatim from sciencec check overlap.science, which exits 1. examples/21_compiler_shapes.science is the harder version of this test: a flat index-keyed table with parent links, a type holding a borrowed array in a field, a boxed recursive tree and a work-queue traversal, all taken from the Rust compiler in crates/ rather than invented, and it passes the borrow checker with no region written anywhere.

What the refusal costs

Removing the syntax removes options with it, and they are named rather than discovered later. There is no RefCell, so no shared mutable state; no Rc, so no cyclic ownership and no child-to-parent back pointer; and an arena that hands out borrows needs unsafe and a hand-written invariant, exactly as Rust's own arenas do. Across a crate boundary the inferred relation has to be serialised into metadata, because a signature that no longer carries its regions cannot be compiled against on its own. A language that says “no annotations” and then needs unsafe for an interner has an asterisk on its headline; this is where the asterisk is.

The rest of it reads the way the audience already writes

choice Phase:
    Solid
    Liquid
    Gas

type Reading:
    kelvin: F64
    pascals: F64

def phase_of(r: &Reading) -> Phase:
    if r.kelvin < 273.15:
        Solid
    else:
        if r.kelvin < 373.15:
            Liquid
        else:
            Gas

def report(r: &Reading):
    match phase_of(r):
        Solid: print(f"{r.kelvin} K: solid")
        Liquid: print(f"{r.kelvin} K: liquid")
        Gas: print(f"{r.kelvin} K: gas")

report(Reading(kelvin: 260.0, pascals: 101325.0))    # => 260.0 K: solid
report(Reading(kelvin: 400.0, pascals: 101325.0))    # => 400.0 K: gas

Built and run the same way. Equality is is and ordering is >=, with no second spelling of either, so a formatter has nothing to normalise and generated code cannot drift. The full surface is in the reference.

Measured against what you already use

Four comparisons, each making one point. The long form — including the ones where Science comes off worse — is in the rationale.

Rust — the same guarantee, none of the notation

denser above is fn denser<'a>(a: &'a Sample, b: &'a Sample) -> &'a Sample in Rust, and the call site is denser(&core, &shell). Science writes neither the parameter nor the ampersands, and still rejects the overlapping-borrow program above with a span on every line involved. The difference is not politeness: Rust's elision rules are a convenience over a syntax that stays available when the guess is wrong, and Science has no syntax to fall back on, so inference has to be total. That is the expensive half of the design, and it is why interprocedural analysis is mandatory here and optional there.

Python — the same mistake, one run earlier

Passing a string where a float belongs is a TypeError in Python at the moment the line executes, which on a training job is after the data has loaded. Here it is a compile error with a span, and the program never starts: 

error[SC0525]: expected `F64`, found `String`
 --> ratio.science:5:15
  |
5 | print(f"{half(reading)}")
  |               ^^^^^^^ this is `String`

sciencec check ratio.science, exit 1. Python's own type hints would have described the same mistake and not stopped it, because nothing in CPython checks them.

Go — the error model, and not the memory model

Science took Go's answer to failure over the alternatives: a function that can fail returns its value beside an error, -> (T, Error?), and ? is a total presence test that produces a Bool and cannot return from the function around it. It did not take Go's answer to memory. The written-down run-time target is scalar code within roughly 20% of an equivalent Rust program, with Go expected behind both, and the reason given is structural rather than effort: no write barrier on pointer writes, monomorphisation instead of one copy per GC shape, and an optimiser that can vectorise. The same note prices the other side honestly — Go is the right target for compile time and the project expects to miss it badly, for the three reasons it lists. Both of those are targets. Nothing has been benchmarked, and no number on this page is a measurement of speed.

C — declared, linked, and nothing in between

There is no header parser, no generated shim crate and no wrapper layer. An extern block is a declaration in the language, and the program below links against libm and runs. 

# libm is a C library nobody is going to rewrite. Declaring it is the whole
# of the binding: no header parse, no generated shim, no wrapper crate.
unsafe extern "C" library "m":
    def cos(x: F64) -> F64
    def sqrt(x: F64) -> F64

let c be unsafe: cos(0.0)
let r be unsafe: sqrt(2.0)
print(f"cos(0) = {c}, sqrt(2) = {r}")
# => cos(0) = 1.0, sqrt(2) = 1.4142135623730951

Built with sciencec build libm.science and run; the trailing comment is the binary's output. The backend itself is held to the same rule: it talks to LLVM through extern "C" against LLVM-C, and no crate in the workspace depends on inkwell, llvm-sys or cranelift — which is a commitment, not an accident, because a Science-hosted backend could not call a Rust wrapper.

Where the compiler actually is

sciencec is version 0.0.1 and there is no installer, no package and no released binary. What follows is split into what has been run and what has not, because a page that overstates is one a single question destroys.

The twenty-second is 17_modules.science, and it fails for a reason worth stating rather than hiding: it opens with use text.parser, and this repository contains no text module, so SC0202 is correct and the file is a fixture ahead of its fixtures. Multi-level modules themselves are not the gap: a fresh two-module crate written for this page — two sibling directories, each with its own add, called as a.add(1) and b.add(1) — checks, builds, links and prints 2 then 3, and science-resolve's own tests resolve a three-file, two-level crate the same way. What is missing is the second file this one example never got, not the feature it exercises.

What is not built, in the compiler's own words

check is much further along than build. The program below passes the whole front half — it lexes, parses, resolves, type-checks and clears the borrow checker — and then the backend refuses it, because nothing above the codegen crate bounds how far a shift may go, and a shift by at least the operand's width is poison in LLVM with neither a mask nor a trap specified to stop it: 

let shifted be 1 << 4
print(f"{shifted}")   # `check` exits 0; `build` refuses, below
error[SC0400]: this `sciencec` cannot build a shift, whose amount nothing above this crate bounds — a shift by at least the operand's width is poison in LLVM and neither the mask nor the panic that would stop it is specified
  = note: this `sciencec` implements §10's stages 0 to 3 of `codegen-and-linking.md` and some of what comes after — a script body, string literals and `print` of anything the `f"…"` builder renders, `extern "C"` declarations and the calls to them, the CFG, scalar arithmetic, functions with parameters, records, `choice`s and `match`, `T?`, methods and associated functions on a concrete type, the prelude's `String` methods, and drops of values that own nothing — and refuses everything else rather than lowering a construct no execution test has ever run

Reaches a binary today

A script body. String literals, print and f"…" interpolation of anything the builder renders. extern "C" declarations and the calls to them. The control-flow graph, including if/else and loop with break. Scalar arithmetic and as casts. Functions with parameters, including & ones. Records, choices, match and T?. Methods and associated functions on a concrete type, including the prelude's own String methods — "Ada".length() and Array[Int].new() both build and run today, which they did not a few days ago. A generic function monomorphises into one linked symbol per instantiation, proven by two calls to the same generic function at two different types producing two distinct symbols in the object file. Drops of values that own nothing.

Does not, yet

A method reached through an interface — a bound, an any Interface, or a default body dispatched to an implementor's vtable slot — still fails at the MIR stage with “Decision 11's method lookup does not put what it found in the tree”: the front end resolves the call and the step that would hand it to codegen loses it. This is why 06_traits, 07_generics, 08_dyn_dispatch and 18_ownership all check clean and none of them build. A handful of specific front-end gaps besides that one: a T? narrowed to a payload that owns something would be freed twice if read out, and that is sometimes refused instead — 09_absence_and_failure.science is — and sometimes not: a nullable choice with a String payload, narrowed with ? and then read through a match, builds with no error at all and the binary segfaults before printing anything, which is a live miscompile rather than a documented limitation and is written up at length, with the exact program, in the rationale. A niched T?'s presence test has no tag to load when the payload is not a pointer-shaped borrow; an if expression over bare integer literals bound directly (let n be if f: 1 else: 0, fixed by writing 1i64); and the shift above. Every one of these checks and exits 0; none of them lowers, and the compiler says so at the point it gives up rather than emitting something it has never run.

Both lists were probed one program at a time against the tree on the day this page was written, not copied from a roadmap, and the boundary between them moves fast — string methods, associated functions and non-method generic instantiation all crossed it since the paragraph above was first drafted. The quoted note is the compiler's own and is the version that ships with it; build on anything in the right-hand column prints its own reason, which is always more current than this paragraph.

The reason the refusals are this specific is a rule the backend is held to: every construct it admits is gated by a program that is built, linked, run and checked for its output. That rule was not free advice. Nine silent miscompiles have been found this way, by running the output rather than reading it — a main that never wrote its return value, an eight-byte store into a one-byte slot that passes LLVMVerifyModule, a needs_drop blind to every runtime aggregate, a lowering hole that suppressed the borrow checker over whole bodies, a pointer-to-pointer the verifier structurally cannot catch, two sibling modules' functions mangling to one linker symbol so one shadowed the other, and a one-element variant payload that handed back a String's byte pointer instead of the value inside it — the last two caught the same afternoon examples/*.stdout started pinning what every example actually prints rather than only whether it exits 0, and both are fixed and reverified directly for this page. Two are not fixed. examples/10_loops.science builds and runs, is one of the ten counted above, and its sixth line of output is an address rather than a number — Array.get returns a niched (&Int)?; narrowing it to &Int and handing that pointer back where the signature promises Int passes the verifier, and the program runs and prints whichever bytes happened to be there. And the read_config program in the rationale's Errors section — a nullable choice with a String payload, narrowed and then matched — builds with no diagnostic and segfaults before it prints anything, verified directly for this page. Both are excluded from the pinned-output corpus rather than patched over, so builds and prints the right answer are not, yet, the same promise for every program on this page — here is where they come apart. In this half of a compiler, silence does not mean it works, and even exit 0 does not always mean it printed the truth, or that it printed at all.

A tenth defect, found while verifying this same build's syntax reference, is not a miscompile: a continue inside a for loop does not misbehave, it simply never finishes. The listing it turned up in only claimed check, not execution, which is consistent with what this section says check does and does not prove — it proves the front end accepted the program, never that the backend runs it to completion.

The toolchain, as it exists

$ sciencec --version
sciencec 0.0.1
$ sciencec check density.science
$ echo $?
0
$ sciencec build density.science && ./density
5778.0 K at 12.5 g

check is silent on a clean file and exits 0, so it drops into a shell script or a CI job without ceremony. Diagnostics go to stderr and dumps go to stdout, which is what makes the dumps pipeable. Every diagnostic carries a code and a span, and where a mechanical fix exists it carries the replacement text too, so an editor or an agent can apply it without reading the prose.

check / build
Run the front half and report what is wrong; then, for build, produce an executable.
fmt
Print the file formatted to stdout, or rewrite it with --write. It refuses any file that does not already lex and parse, because reformatting a guessed token stream is how a formatter eats a program.
tokens / ast / resolve
Dump the token stream, the syntax tree or the resolved crate, for when you want to see what the compiler saw.
tools --json
A JSON Schema for every tool in the file, derived from the signature rather than written beside it.
