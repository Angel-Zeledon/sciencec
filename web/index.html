The compiler checks your units, your shapes and your random keys.

Science is a compiled language for scientific computing and machine learning. Native binaries through LLVM, ownership and borrows verified at compile time, no garbage collector and no lifetime annotations to write. Built for people who arrive from NumPy and PyTorch, not from systems programming. 

$ git clone https://github.com/sci-lang/science && cd science
$ cargo run -p sciencec -- check examples/01_functions.science

Three things nobody checks, checked

Julia has the REPL and the ecosystem and cannot check a shape, a unit or a reused random key before running. Mojo has ownership and GPUs and no shapes in its types. JAX has the right transformation model and no static types. Science aims at the combination.

Units

A dimension lives in the type. Adding a mass to a length does not compile, and neither does a conversion applied twice. The Mars Climate Orbiter failure, moved from the run to the build.

Shapes

A tensor carries its shape as type arguments, so a matrix multiply whose inner dimensions disagree is a compile error. Broadcasting is explicit: a .+ b says you meant it; a + b requires the shapes to match.

Random keys

A key is consumed when it is used, so reusing one is a compile error rather than a silently correlated result. JAX has the design. A language can enforce it.

What that looks like when you get it wrong

   |

   |
   = difference: m/s

   |
14 |     let energy: Energy of F64 be mass * speed ** 2
   |                                               ++++

Every diagnostic carries a code, a span and — where a mechanical fix exists — the replacement text, so an editor or an agent can apply it without reading the prose.

The language

Keywords are English words where no symbol is universal, and symbols where one is. Blocks are indentation. There is exactly one way to write each operation.

Types and interfaces

type Doc:
    title: String
    body: String

interface Summarize:
    def summarize(self) -> String

    # A default body may call any
    # other method of the interface.
    def preview(self) -> String:
        self.summarize().truncate(80)

Doc implements Summarize:
    def summarize(self) -> String:
        self.body.truncate(200)

Generics and bounds

def best_of of T(
    left: borrowed T,
    right: borrowed T,
) -> String where T: Summarize:
    if (left.summarize().length()
            >= right.summarize().length()):
        left.preview()
    else:
        right.preview()

# Const generics carry shapes.
type Grid of (T, const ROWS: Int):
    cells: Array of T

Closures have a type, with no keyword

def apply(f: (Int) -> Bool, x: Int) -> Bool:
    f(x)

# Right-associative, and `?` binds tighter than `->`,
# so a nullable closure needs its own parens.
type Pipeline:
    step: ((Int) -> Bool)?
    stages: Array of ((Int) -> Bool)

Const generics do arithmetic

type Grid of (T, const N: Int):
    cells: Array of T
    padded: Grid of (T, N + 1)
    tripled: Grid of (T, N * 3)
    doubled: Grid of (T, 2 * N)

Borrows, with nothing to annotate

def retitle(doc: mutable borrowed Doc, title: String):
    doc.title be title

def main():
    let mutable doc be Doc(title: "a", body: "")

    # A parameter declared `borrowed` is borrowed automatically, so the call
    # site is bare. The signature still carries the information.
    retitle(doc, "renamed")

Regions are inferred, including across function boundaries. There is no 'a to write and no garbage collector underneath — the guarantee without the notation.

Chains, which is the shape most code takes

def headlines(docs: borrowed Array of Doc) -> Array of String:
    docs
        .iterate()
        .discard(each.is_empty())
        .map(each.title)
        .take(5)
        .collect()

Your existing code still works

Essentially every floating-point operation that matters already lives in a C or Fortran library somebody else tuned. dgemm is thirty years of hand-written assembly per microarchitecture. A language that cannot call these is not a scientific language, whatever its type system can prove.

C and Fortran, declared and linked

unsafe extern "C" library "openblas" via pkg-config "openblas":
    type CblasLayout is CInt
    const CBLAS_COL_MAJOR be 102 as CblasLayout

    def cblas_dgemm(
        layout: CblasLayout,
        m: BlasInt,
        a: ffi.Span of F64,
    ) symbol "cblas_dgemm"

via pkg-config takes the flags from the system, which is the only thing that gets BLAS right across machines. when available makes a library optional and loaded on first use, so a program that can use a GPU still starts on a node without one.

Python, zero-copy
A tensor's header is a DLPack DLTensor field for field, so handing an array to NumPy, PyTorch or JAX is a cast rather than a copy.
Called from Python
Compile a file into a CPython extension module and replace one hot function inside the program you already have.
Rust crates
Bindings generated from a crate's own public interface, with layout and signature assertions discharged by rustc itself.
Arrow and Parquet
A dataframe column is an Arrow buffer, so the handoff to polars or DuckDB costs nothing.

A tool a model can call, with no schema to write

An MCP server makes its tools discoverable by publishing a JSON Schema for each one. Every SDK for it asks you to write that schema beside the handler and keep the two in step by hand; Python’s reads the signature back at run time, TypeScript’s takes a schema you hand it. Science has neither reflection nor a way to check that two artefacts agree, so the schema is derived from the signature or the claim is empty. 

choice Lineshape:
    Gaussian
    Lorentzian
    PseudoVoigt

## Integrates a spectral peak under a chosen line shape.
tool integrate_peak(counts: Array of F64, window: U16,
        profile: Lineshape) -> F64:
    0.0
$ sciencec tools --json peaks.science
[{"name":"integrate_peak",
  "inputSchema":{"type":"object","properties":{
    "counts":{"type":"array","items":{"type":"number"}},
    "window":{"type":"integer","minimum":0,"maximum":65535},
    "profile":{"type":"string",
               "enum":["Gaussian","Lorentzian","PseudoVoigt"]}},
    "required":["counts","window","profile"]},
  "description":"Integrates a spectral peak under a chosen line shape."}]

Nothing in that output was written twice. window is a U16, so the model is told the value is between 0 and 65535 — a bound no other SDK’s int carries. Lineshape is an ordinary choice, which is how Science already spells alternatives, and it arrives as the exact set of strings the tool accepts. The description is the ## comment, because the description is what a model reads to decide whether to call the tool: it is program data, not documentation, and a tool without one does not fail — it is simply never chosen.

One thing is deliberately missing. A U64 gets minimum: 0 and no maximum, because 264−1 cannot be written exactly as a JSON number and emitting it would be a lie about what the caller can send.

Decisions you will notice

One spelling per operation
Equality is is, ordering is >=. No second way to write either, so a formatter has nothing to normalise and generated code cannot drift.
Fixes, not just messages
A diagnostic carries the replacement text and the span it applies to. Errors never cascade: one mistake costs one message.
Explicit broadcasting
NumPy will happily add a (3,1) to a (1,3) and hand you a (3,3) you did not want. Here that needs a dot.
Reproducible by construction
No ambient random generator, no seed(), and a provenance record in the binary that names every library it linked.

Install

There is no installer, no package and no released binary yet — sciencec is version 0.0.1 and lives only as source. Building it needs a Rust toolchain and nothing else; the workspace has exactly one third-party dependency. 

$ git clone https://github.com/sci-lang/science && cd science
$ cargo run -p sciencec -- check examples/01_functions.science
$ echo $?
0

Your first program

$ cargo run -p sciencec -- check hello.science
$ cargo run -p sciencec -- fmt hello.science
$ cargo run -p sciencec -- tools --json hello.science

check is silent on a clean file and exits 0, so it drops into a shell script or a CI job without ceremony. fmt prints the file formatted to stdout, and refuses to touch one that does not already lex and parse. tools --json prints a JSON Schema for every function in the file, derived from the signature alone. Diagnostics go to stderr; dumps of the tokens, the syntax tree and the resolved definitions go to stdout, for when you want to see what the compiler saw.

What the compiler does today

sciencec lexes, parses, resolves, formats and emits tool schemas. build exists now and does real work — layout, the C ABI, symbol mangling, monomorphisation — and then stops cleanly, because there is no LLVM backend compiled in on the machine this site is written on: 

error[SC0400]: no `llvm` backend is compiled into this `sciencec`
  = note: `science-codegen` computes layout, the C ABI, symbol names and the runtime boundary, but emitting an object file needs a backend and none is linked in
  = note: install LLVM 18.1.8 — `winget install LLVM.LLVM --version 18.1.8` or `choco install llvm --version=18.1.8` — then set `LLVM_SYS_181_PREFIX` to the install root, and rebuild `sciencec` with the `science-codegen-llvm` backend

Type checking and region inference still are not wired into the driver, so build's middle is a well-defined gap rather than a filled one — what runs today is check's lex-parse-resolve, then codegen's target-independent half directly. Everything on this page and in the reference is the language as designed, and most of it is already what sciencec lexes, parses and resolves — including the error model, which used to be the exception here. A function that returns a pair — -> (Config, Error?) — the nullable type T?, the presence test ? and the literal null all parse and resolve today. What is not built is what they mean: the narrowing that makes if err?: tell the compiler err is not null, and the diagnostic that refuses a returned error nobody tested. Both need a type checker, and there is not one wired in yet. The reference shows both forms and says which is which.

Documentation

The specification is the authority. The design notes decide one area each, state what they rejected and why, and price what they ask of the others.

Language reference → Syntax, ownership, interfaces, foreign code and the toolchain, in one page. The specification → Phases, syntax, types, ownership, diagnostics. What the compiler is held to. Design notes → Forty-two areas decided in the open, each with the alternatives it rejected. Examples → Worked programs, one per feature, used directly as the compiler's test data.

The example programs are input data for the test suites, so anything there that fails to compile is a bug in the compiler rather than a typo to be quietly patched. Programs that must fail, each paired with the exact diagnostic it has to produce, live beside them.

Source

Nine crates behind one driver, and all nine are real — nothing below is a placeholder for a crate that does not exist. The compiler is a set of memoised queries over a shared database rather than a pipeline, which is what will make recompilation incremental once there is more to recompile.

science-lexer
Tokens, indentation, literals.
science-parser
Grammar, syntax tree, extern blocks.
science-resolve
Names, scopes, definitions.
science-types
Type checking, traits, const generics — building, not yet called by check.
science-fmt
The formatter behind sciencec fmt.
science-db
The query database every other crate reads through.
science-diagnostics
Rendering, spans, applicable fixes.
science-codegen
Layout, the C ABI, mangling, monomorphisation — the half of code generation that does not need a backend.
science-rt
The runtime every binary will link, once a backend can call it.

Ownership and region inference do not exist yet even as an empty crate — there is no science-regions today, and nothing calls it into check. Nor does the other half of code generation: science-codegen hands a finished lowering to a backend, and the LLVM one, science-codegen-llvm, is deliberately absent, because it needs an LLVM 18.1 installation and a workspace nobody can build without one is a workspace nobody can contribute to. Until it exists, sciencec build gets exactly as far as the reference shows and stops.
