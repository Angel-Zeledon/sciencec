What you can write

This page answers one question: is this expressible in Science, and how is it spelled? Every construct the language has, with its shape and a program that compiles. Every word the lexer knows, with whether it means something today. The precedence table read off the parser rather than off a note. And — because a reference that omits this is the one that costs a reader an afternoon — the constructs that parse and are not built, named with the diagnostic each one currently produces.

The reference explains what a construct means and why the language has it. The rationale argues for the spelling against the ones it beat. This page is the inventory: shorter on argument, complete on coverage.

How every listing here was verified, and what the verdict means

Thirty-seven Science listings below were extracted from this file's own source, written to scratch files and run through sciencec check. Thirty-six report nothing. The thirty-seventh is the IndexMutably block in Parses, and is not built, which is on this page in order to fail and whose diagnostic is printed beneath it. One further block shows removed syntax, carries a grey rail and a caption, and is not valid Science, so it is not one of the thirty-seven. One listing — modules — needs a sibling file beside it, which is written out under the block, and it checks clean with that file in place.

Ten listings carry a trailing # comment holding their real stdout, compiled with sciencec build and executed, and every one of those ten matched. They were not all run in the same pass: a listing keeps its output comment only for as long as somebody has seen the program print it, and one is removed rather than guessed at the moment it cannot be reproduced.

A listing with no output comment was checked and not run, and that is the majority of them, usually because it uses a construct the LLVM backend refuses: the backend implements the first four lowering stages, so a method call, an Array, a generic, a loop, integer / and %, and a shift all check and none of them build. That distinction is stated rather than blurred, because check accepts a great deal more of this language than build emits. check needs no backend at all, which is why it is the measurement this page rests on.

Every diagnostic reproduced on this page is the compiler's own stderr, run and pasted, down to the span underlines. Where a construct is specified and unbuilt it is in Parses, and is not built with the error it produces — never in a section above as if it worked. Nothing on this page is syntax somebody wished for.

That list shrinks, and when it does the entry says so rather than vanishing. Two of the six moved while this page was being extended. The array literal, which used to parse and never be type checked, is checked now: SC0281 and SC0282 exist, both of its listings stopped checking clean, and what was item 3 is a note inside its replacement. A range index, which used to check clean and quietly hand back one element, is now SC0538 and says what it means. A reference that deleted those two paragraphs would leave a reader no way to judge how stale the other four are.

The shape of a file#

A file is a module. Its top-level statements are its program, so the smallest whole Science program is one line and there is no main to write. Blocks are indentation, opened by a :. Comments are # to end of line; ## is a doc comment and attaches to the declaration below it. The lexical rules are in Tokens, identifiers, whitespace, the three kinds of comment in Comments, and the block and continuation rules in Indentation, newlines, continuation. 

print("lift-off")
# lift-off
$ sciencec check hello.science
$ echo $?
0
$ sciencec build hello.science
$ ./hello
lift-off

check printing nothing is the verdict. Diagnostics go to stderr and dumps to stdout, and the exit code is 0 when nothing was reported as an error — warnings alone do not fail.

A function body's last expression is its value; there is no implicit return anywhere else. A file may have top-level statements or a main, and not both — two answers to "what runs first" is SC0117, and what a top-level statement binds is in Scope and shadowing.

Seven, and const is not one of them. const NAME be v is a declaration, so it lives at the top level of a module and not in a body: writing one inside a def is SC0105, "expected an expression, found const". That is the rule that makes a constant visible to every item in the file, which a statement could never be.

Tokens, identifiers, whitespace#

A source file is UTF-8 text and nothing else — no byte-order-mark rule, no encoding pragma, no include. The lexer turns it into a stream that always ends in Eof, and it recovers from every error rather than stopping, so a stray character costs one diagnostic and the rest of the file is still read. Four of the token kinds are synthetic: they stand for line structure, they have no characters of their own, and they are what makes indentation a grammar rather than a convention.

A fifth kind, Hash, is never emitted at all — it exists against the day # stops meaning a comment. A page that listed them among the syntax would be describing the token table instead of the language, so they are named here and nowhere else.

What may be an identifier

An identifier starts with _ or any character Unicode calls alphabetic, and continues with _ or any alphanumeric one. That is the whole rule, and it is why a Greek letter is an ordinary name rather than a concession — which matters for a language whose programs are meant to be read beside the paper they came from. Case is significant and carries no meaning of its own: Doc and doc are two names, and nothing in the grammar requires a type to be capitalised.

What is whitespace

Between tokens a space, a tab and a carriage return separate and mean nothing else, so a file indented with spaces and aligned with tabs inside a line is one program however it is displayed, and a CRLF file is the same program as an LF one. In the indentation the rule is different and stricter: only spaces count, a tab there is SC0003, and a lone carriage return before the break carries no width. The reason is in the diagnostic — a tab's width depends on how the file is displayed, so a block indented with one would mean different things to two readers of the same file. The cost is that the same character is legal in one column and an error three columns to its left.

The language sets no line length. sciencec fmt targets 90 columns and indents by four spaces, and neither number is a rule the compiler enforces.

Comments, documentation, pragmas#

One character opens all three kinds and what follows it decides which: # is an ordinary comment, ## is documentation that the compiler reads and ships, and # fmt: off is an instruction to the formatter. All three run to the end of the line. There are no block comments, and there is no nesting to get wrong, because a comment ends where the line does and nothing reopens it. 

# An ordinary comment runs to the end of the line. There are no block
# comments, so a paragraph is a run of these.

#No space after the hash is required.
# A comment may hold a "string", a 'c', an 0xFF, and words that would be
# keywords anywhere else: def return let be mutable type choice giving.
# It may hold anything Unicode can spell.

def tally(n: Int) -> Int:
    # A comment as the first thing in a block.
    let mutable total be n  # a trailing comment after a statement

    # A comment-only line inside a block, after a blank one.

    total be total + 1
    total

print(f"{tally(1)}")
## Counts the samples above a floor.
##
## The first line is the summary. The whole run is the description, summary
## included, and `sciencec tools --json` emits it verbatim.
tool count_above(samples: Array of F64, floor: U16) -> Int:
    samples.length()

## A run attaches to the next token that has text of its own, so the newline
## and the indent between this run and `def` pass straight over it.
def unused() -> Int:
    0

print(f"{unused()}")
# 0

# — the ordinary comment

Everything from the # to the line break, and nothing else. A comment-only line and a blank line take no part in the indentation calculation, which is what lets a comment sit at any column without opening or closing a block — a comment written at column 0 in the middle of a function does not end the function, and one indented past every open level does not start one. That rule is the reason the language can afford to be indentation-delimited and still let you write a note wherever the note belongs.

## — the documentation run

A doc comment is trivia, not a token. Making it a token would put it in every match over token kinds in the parser, for a thing the grammar never mentions; instead the lexer accumulates a run of consecutive ## lines and hands it to the next token that has text of its own. Newline, Indent and Dedent pass over it without consuming it, and that is precisely what lets a run survive the line break and the indent that always sit between it and the declaration it documents.

# fmt: — the formatter's three pragmas

sciencec fmt is idempotent and has one canonical layout, so the only thing it can offer is an exception. There are three, and they are ordinary comments to every other pass — the compiler does not know they exist.

WrittenDoes
# fmt: offSuppresses formatting from this line until the matching # fmt: on. Both marker lines are inside the region and are reproduced.
# fmt: onEnds the region. On its own, with no off above it, it is an ordinary comment and is never warned about.
# fmt: skipSuppresses the next statement — the next logical line, however many physical lines that spans, along with anything written between the marker and it.
 
$ cat held.science
# fmt: off

let x     be 2
# fmt: on
let y     be 3
$ sciencec fmt held.science
# fmt: off
let table be 1
let x     be 2

let y be 3

The spelling is exact and the compiler will not tell you when you miss it. Exactly one #; then, after any amount of whitespace, the literal text fmt: off, fmt: on or fmt: skip, and nothing else on the line. So #fmt: off works and # fmt:off does not; ## fmt: off is a doc run and never a directive; # FMT: OFF is a comment; # fmt: off for now is a comment. There is deliberately no diagnostic for a near miss, which is the cost: a mistyped marker is silently inert.

Indentation, newlines, continuation#

Indentation is how every block in this language is delimited. There is no {, no end, no begin. A : at the end of a line opens a block; indenting past the level above emits Indent; indenting back emits one Dedent per level closed. Because the lexer does this, a block is a grammatical object the parser matches on, and a misplaced line is a diagnostic with a caret rather than a program that quietly means something else.

The rules, in full

RuleWhat follows from it
Spaces only.A tab in the indentation is SC0003. Recovery gives the line the level currently on top of the stack rather than guessing a width, so one tab costs one diagnostic and not a cascade.
Any width opens a level.The language names no number. Four spaces is what sciencec fmt writes and not what the compiler requires.
Dedenting must land on an open level.Otherwise SC0004, which lists the levels that are open. Recovery pushes the width as a new level so the stream stays balanced.
One Dedent per level closed.A statement at level 6 followed by one at level 1 emits five. Closing many levels at once is the case that breaks a naive indentation stack, so the corpus goes eight deep on purpose.
Blank and comment-only lines take no part.They are skipped before the width is measured, so neither opens or closes anything, whatever column it is written at.
The file ends the last line and closes every block.A file with no trailing newline still gets its Newline, and Eof is preceded by every outstanding Dedent. The parser sees one shape and not two.

Line continuation — the two things that do it

Every line break ends a statement, except two, and both are written at the start of the continuing line. A reference that omits this is the reason a reader believes a five-line chain is five statements.

ContinuesRule
( [ {While any bracket is open the line structure is suppressed entirely: no Newline, no Indent, no Dedent, and the indentation inside is decorative. This is what makes one-argument-per-line formatting work.
.A line whose first character is . and whose next character can start an identifier continues the line above. That is how a method chain breaks.
whereA line beginning with the word where continues the line above, so a long signature breaks before its bounds. No statement may begin with where, so recognising it here costs nothing.

.. is excluded from the . rule deliberately: a range is not a chain link, and no line may begin with one. The rule is written as "a . followed by an identifier start", which also means a leading .0 continues nothing — consistent with there being no t.0 to reach for. Blank and comment-only lines take no part here either, so a comment in the middle of a chain does not break it.

def and tool#

def declares every function, method, associated function and interface member the language has. There is one word for all four, and the thing that tells them apart is where the declaration sits and whether its first parameter is self.

The shape is def name(param: Type, …) -> ReturnType: and an indented body. The return arrow is omitted when there is nothing to return; the function's type is then (). Parameters are always annotated — inference is local to a body and stops at a signature, so a signature is the one place a type is never guessed. The body's last expression is its value. 

def area(width: Int, height: Int) -> Int:
    width * height

def greet(name: borrowed String):
    print(f"hola, {name}")

def clamp(value: Int, low: Int, high: Int) -> Int:
    if value < low: return low
    if value > high: return high
    value

print(area(6, 7))
greet("Kepler")
print(clamp(120, 0, 100))

That listing checks and does not build: print of a non-String needs a vtable the backend does not emit. The same three constructs, with the values sent through an f"…" instead, do build: 

def area(width: Int, height: Int) -> Int:
    width * height

let w be 6
let h be 7
print(f"{w} by {h} is {area(w, h)}")
# 6 by 7 is 42

tool — a function a model may call

tool is a second declaration form, not a synonym for def, and it exists because it carries five obligations a def does not and a compiler can check: every parameter type has to survive a round trip through JSON Schema, the declaration may not be generic, no parameter may be borrowed, it must carry a ## description, and its return type is constrained. A marker that changes nothing would be an attribute; five checkable obligations are a declaration form. 

## Count the peaks above a threshold in one run.
##
## Returns the number of peaks, or zero when the run is empty.
tool count_peaks(run: String, threshold: Int) -> Int:
    if run.is_empty(): return 0
    run.length() + threshold

print(count_peaks("abc", 2))

The description is not documentation the compiler tolerates — it is an argument, and the schema below is derived from the signature rather than written beside it. An Int becomes an integer with its width, which is a claim no other tool SDK's int can make.

type and choice#

Scope and shadowing#

A name is visible from where it is bound to the end of the block that binds it, and nowhere else. Items are the exception: a def, a type, a choice, an interface and a const live in a table of their own and are visible throughout the file regardless of order, which is what lets two functions call each other without a forward declaration.

A name may be rebound, and it shadows

A second let on the same name in the same block is legal, silent, and shadows the first. The new binding may have a different type, and its initialiser is resolved before any of its names are defined — so let n be n + 1 reads the old n and then hides it. There is no warning, because the feature exists in order to be used: narrowing a value through a series of steps without inventing n2 and n3 is the whole point.

What a top-level statement binds

A file whose top level holds statements is a script: the compiler wraps those statements in the main it writes for you. So a top-level let binds a local, not a module-level name, and the consequence surprises people — it is invisible inside a def in the same file, because a function body is a different scope and the module table holds items only. 

error[SC0200]: cannot find `top` in this scope

  |

  |     ^^^ not found

Written out: let top be 7 at the top of a file, then def uses_top() -> Int: with top as its body, does not check. Pass the value as a parameter, or make it a const — a const is an item and is in scope everywhere in the file.

Two consequences of the same rule are their own diagnostics. SC0117: a file may have top-level statements or a hand-written main and not both, because two answers to "what runs first" is not a question the compiler should pick for you. SC0213: top-level statements in a module that is not the entry point are an error, because Science does not run a module's statements when it is imported, so they would never run at all.

A local shadows a module too. text.parser folds into a module path only when no enclosing block holds a binding called text; bind that name and the path becomes a field access on your value, which is the reading you asked for. Reserved words cannot be shadowed because they cannot be bound at all: let model be 1 is SC0102, "expected an identifier, found model, which is reserved for a later phase". each is a keyword for that exact reason — no user binding can collide with the one a closure invents.

The where clause

A bound may be written in two places and they mean the same thing. Inline — def f of T: Summarize(…) — puts the constraint where the parameter is introduced, which reads well when there is one of each. A where clause puts every constraint after the signature instead, which is the only form that stays readable when a parameter carries three bounds or a declaration carries three parameters. The cost of having both is that a reader has to look in two places; the reason for paying it is that a signature is the thing most often read and least often edited, and a line of bounds in the middle of it hides the parameters. 

interface Summarize:
    def summarize(self) -> String

interface Clone:
    def clone(self) -> Self

def inline of T: Summarize(value: borrowed T) -> String:
    value.summarize()

def clause of T(value: borrowed T) -> String where T: Summarize:
    value.summarize()

def several of (A, B)(left: borrowed A, right: borrowed B) -> String
        where A: Summarize, B: Summarize + Clone:
    right.clone().summarize()

def both of T: Summarize(value: borrowed T) -> String where T: Clone:
    value.clone().summarize()

Both forms on one declaration is legal and is not a diagnostic. both above declares T: Summarize inline and T: Clone in the clause, and the checker reads the two lists and concatenates them, so T is Summarize + Clone. The syntax tree keeps them apart deliberately — a diagnostic has to be able to point at where the programmer wrote a bound, not at where the compiler filed it.

What an unsuffixed number is

A numeric literal is inferred, not defaulted — and inferred among the numeric types only. 42 does not arrive as an Int and then get converted; it arrives as an integer literal, joins whatever type the expression around it pins it to, and falls back to I64 — or F64 for a float — only if nothing constrains it at all. That is why let n be 42 followed by takes(n) at an I8 parameter checks, and why 1 + 1u8 makes the 1 a U8 rather than a width error.

The inference is among numbers and not a wildcard, which is the whole difference from a hole. Handing that same n to a String parameter is SC0525, and the diagnostic names the pending type by what it is: 

error[SC0525]: expected `String`, found `an integer literal`
 --> pending.science:5:13
  |
5 | print(wants(n))
  |             ^ this is `an integer literal`

An integer literal is accepted at a floating position — let x: F64 be 1 — because that is what a scientific program writes and 1 is exact there. A float literal is not accepted at an integer one: let n: I32 be 1.5 is a value the target cannot hold, and admitting it is how a language becomes wrong on somebody's index arithmetic.

else if, and the two block shapes

Every block in the language is one of two shapes and they mix freely: a : then a newline and an indented body, or a : then a single statement on the same line. else if is not a third thing and not a keyword — it is an else whose body is an if, which is why it takes no : of its own and why there is no elif to remember.

Absence and failure#

Two shapes, and they are deliberately the same shape. Absence is T?: a value of that type is a T, or it is null. Failure is a second return value: -> (T, E?), so a function that can fail hands back what it produced and what went wrong. ? is the postfix presence test — err? is a Bool — and after if err?: return … the compiler knows the value is good.

The hole in that check, and why this entry is the softest on the page

The condition the design states is "E? where E implements Error", and read literally that is silent on the program the language itself recommends: a function naming a concrete choice as its error so the caller can match on it exhaustively, with no implements Error block. The corpus writes exactly that. So the one construct that recovers what a Result guaranteed had a shape it did not cover, and the shape was the recommended one.

That coverage is being changed as this page is written, so it is the one claim here not worth pinning to a number: the rule is moving from the error type to the error position — the last binding of a several-binding let, of nullable type, whose initialiser is a call. Check it against your own compiler before relying on it either way. The advice that survives the change is unchanged: if you take the concrete error form for the match it buys, test the error by hand and do not wait to be told.

There is no Option, no Result, no Some, no None, no Ok, no Err, no try, no unwrap and no is_some — because there is no wrapper type left for those methods to hang off. ? is the only operation a nullable has.

Three places the design notes and the lexer disagree

1. The audit asks to free eight words, and all eight are still held. shape, model, tensor, mod, yield, kernel, union and import are each marked Free in reserved-words.md §5, and from_word maps every one of them to Reserved(…) today. The recommendation was strengthened rather than withdrawn — §6 records that the F1 design has since confirmed it wants no shape declaration, so the reservation protects a construct nothing asked for — and it has not been acted on.

2. The dot rule is not implemented. §0.1 of that note asks for one function: after a ., accept any word as a member name, because no keyword can begin anything in that position. It calls the change "required regardless of every other decision here". The parser still calls expect_ident after a Dot, so x.shape, a.union(b), values.any(), re.match(s), n.mod(m) and frame.import() all fail — and g.shape produces three errors rather than one, because the parser cannot resynchronise on a word it refused.

3. There is no SC0002. §5.1 of the note describes SC0002 as "a word reserved for a later phase used as a name" and asks for its message to gain a fix. No such code exists in any crate; a held word surfaces as whatever the parser wanted there instead — SC0102 in binding position, SC0105 in expression position — which is true and useless, exactly as the note predicted for the member case. The core spec's §13 also still lists tool, extern and unsafe as "reserved, not yet used", and the lexer makes all three live keywords.

Parses, and is not built#

Six constructs get through the parser and stop somewhere after it. A page that listed them beside the working forms would be worse than one that omitted them, so they are here, each with the diagnostic it produces today — or, in two cases, with the fact that it produces none, which is the more expensive kind.

1. a[i] be v reaches an interface you cannot supply

Indexing is two interfaces: Index reads and yields borrowed Output; IndexMutably writes and yields mutable borrowed Output. a[i] be v parses, dispatches to IndexMutably, and works for the built-in Array. Writing your own is where it stops: the obvious implementation reads through the backing Array, an index read yields borrowed T, and nothing in the language turns that into a mutable borrowed T. 

type Grid:
    cells: Array of Int

Grid implements IndexMutably of Int:
    type Output is Int

    def index_mutably(mutable self, at: Int) -> mutable borrowed Self.Output:
        self.cells[at]

let mutable grid be Grid(cells: (Array of Int).new())
grid[0] be 9
error[SC0525]: expected `mutable borrowed Int`, found `borrowed Int`
 --> writing.science:8:9
  |
8 |         self.cells[at]
  |         ^^^^^^^^^^^^^^ this is `borrowed Int`
1 error

Writing mutable borrowed self.cells[at] does not rescue it — that is mutable borrowed borrowed Int. What does check is an IndexMutably whose output is reached through a field rather than through an index, so the interface is implementable and the container it is wanted for is not.

2. Slicing does not exist, in two different ways

a[1..5], a[2..], a[..5] and a[..] are all specified as index-bracket forms, and a range index is specified to produce a Slice of T — a borrow and a length, which does not copy. None of the four works, and the two halves fail at different stages.

The open-ended forms do not parse: parse_range requires both ends, because an open end would have to be told from a .. that ends a line. 

error[SC0105]: expected an expression, found `]`
 --> slice.science:2:19

The closed form parses and is refused by the type checker, which is the better of the two failures and was not always the case: this used to check clean and hand back borrowed Int — one element rather than a slice — because the untyped range and the Int the Index implementation wanted agreed by cancelling instead of by matching. It now says what it means.

There is no Slice in the prelude to name either: Slice of Int in a signature is SC0200, "cannot find Slice". Index one element at a time, or iterate.

3. A where predicate on anything but a bare parameter is discarded

A clause's subject is read by the full type grammar, so where Array of T: Ord, where borrowed T: Ord and where Int: Ord all parse. The checker then keeps a predicate only when its subject is a bare, argument-free name resolving to a generic parameter the declaration itself introduced, and drops every other predicate — no diagnostic, no note, no warning. The listing below checks clean, and D implements Ord nowhere. 

interface Ord:
    def cmp(self, other: borrowed Self) -> Int

type D:
    v: Int

def held of T(x: borrowed T) -> Int where Array of T: Ord, borrowed T: Ord, Int: Ord:
    0

def calls(d: borrowed D) -> Int:
    held(d)

print(f"{calls(borrowed D(v: 1))}")

The bare form is checked properly, and the difference is the measurement: change that clause to where T: Ord and the same call is SC0534, "D does not implement Ord", with the declaration site pointed at as well. So the failure is not that bounds go unchecked — it is that a bound the checker does not recognise looks exactly like one it satisfied. Write the subject as a bare parameter name, and put anything else in the body, where it will be checked.

What used to be here, and is not any more

This slot held the array literal, which parsed and was not type checked at all: let counts: Array of String be [1, 2, 3] checked clean, and let counts be [1, 2, 3] left its binding at the error type with no diagnostic, so every check downstream of it was vacuous. SC0281 — the code the design allocated for exactly this — was defined in no crate. It is defined now, and a second code, SC0282, covers the empty literal that has nothing to take an element type from. Both forms are in Literals as working syntax. This paragraph is here rather than deleted because a reference that quietly drops a hole teaches the reader nothing about how far to trust the rest of the list.

4. The format mini-language is specified and unbuilt

Fill, alignment, sign, width, grouping, precision, the type codes and the !i conversion are all designed, and checkable at compile time against the argument's static type. None of it exists. The compiler refuses a specification rather than parsing and ignoring one, which would look supported.

5. SC0286 — bounds checking — does not exist

The design gives every a[i] an index obligation — 0 <= i and i < extent — discharged statically where it can be, and warned about under SC0286 where it cannot. No pass discharges one and no crate defines the code; the whole SC0280–SC0289 band is unallocated. An index is unchecked at compile time and the runtime fallback is a panic that has never run.

6. Interpolating a narrowed T? emits an invalid module

Four lines, checking clean, that the backend miscompiles. The nullable's two-word representation is handed to a runtime entry point that takes one word, and LLVM's own verifier catches it before the linker is reached.

No comprehensions

One form per operation. A comprehension and a chain do the same thing, and keeping both means every reader learns both and every author picks. The chain is the one kept, because it reads in the order it runs and it composes past three links where a comprehension does not.

A comprehension is caught on the syntax tree, before types, and that is deliberate: a comprehension type-checks as nothing at all, so a phase that let it through would report the absence of a chain three times and the comprehension never.

No lifetime syntax

There is nothing to write and nothing elided. <'a> is not a form the grammar knows, and the parser meets it as a < where it wanted a (, then as a character literal that never closes — four errors for a construct that does not exist, which is the honest failure of a grammar with no slot for it. The bet is stated in the type vocabulary: a borrow checker with nothing to annotate is either sound or it is a bug.
