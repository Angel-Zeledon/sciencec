Language reference · F0

Science

A compiled language for scientific computing and machine learning. Native binaries through LLVM, memory managed by ownership and borrows verified at compile time with no garbage collector and no lifetime annotations. Blocks are indentation; keywords are English words where no symbol is universal, and symbols where one is.

This page is written for somebody who knows Python and NumPy and has never written Rust. Each section says what a construct is, why the language has it, how it behaves at the edges, and what it costs — because a syntax sample shows you the first of those and none of the other three.

What this page is, and what the compiler is

This page describes syntax revision 3, which is the language as designed. Almost all of it is what sciencec lexes, parses and resolves today, and every Science block below that is a whole module was run through sciencec check before it was pasted here — twenty-five of them, all green. One block is a fragment: correct Science that is not a complete file, because its use line names a module that would have to exist beside it. One more shows removed syntax on purpose. Both say so where they stand.

What does not exist is the second half of the compiler. There is no code generator you can run, so no Science program has ever been compiled or executed. There is no type checker wired into check, so everything here that depends on types is parsed, resolved, and then nothing looks at it. Two named consequences run through the Errors section and are marked changing wherever they bite: the narrowing that is supposed to make if err?: tell the compiler that err is not null, and SC0140, the check that refuses a returned error nobody tested. Both are decided, both are specified, and neither is built. Where that is true this page says so in the sentence, not in a footnote.

Getting started#

A file is a module. There is no project file, no manifest and no scaffolding beyond a main. Save this as hello.science. 

type Doc:
    title: String
    body: String

def main():
    let doc be Doc(title: "Regions", body: "A region is a set of program points.")
    print(doc.title)

    for i in 0..3:
        print(i)
$ sciencec check hello.science
$ echo $?
0

Four things in eight lines are worth naming before anything else, because each is a place a Python reader's expectations will quietly disagree with the language.

Blocks are indentation, and only spaces. A tab in the indentation is SC0003 with no attempt to guess a width. That is stricter than Python, which resolves the mixture by a rule most people could not state, and it is strict for a stated reason: a tab's width depends on how the file is displayed, so a file indented with both would mean different things to two readers of the same bytes.

let … be, not =. The word is there because = has two unrelated meanings in the languages this audience writes — binding in a program, equality in a paper — and a language that keeps the symbol for binding has to spell equality == to get out of the way. Science keeps the mathematical reading: is compares, be binds, and neither has a second spelling.

Doc(title: …, body: …) constructs with named arguments, in any order. Ordinary function calls are positional; record construction is not, and the asymmetry is deliberate. A record's fields have names the author chose, and a constructor call that lists four strings in an order you have to look up is one of the commonest places a program is silently wrong.

check is silent on a clean file and exits 0. It drops into a shell script or a CI job without ceremony. Anything it finds goes to stderr with a code, a primary span and, where a mechanical fix exists, the exact replacement text, so an editor or an agent can apply it without reading the prose. Dumps go to stdout. Warnings alone do not fail the run.

Bindings and literals#

let … be introduces a name. be on its own assigns to one that already exists. A binding is immutable unless it is declared mutable. 

const WIDTH be 768                 # a compile-time constant
type Embedding is Array of F32     # a type alias

def main():
    let title be "Regions"         # immutable, and the type is inferred
    let mutable count be 0         # `mutable` is what makes assignment legal
    let width: Int be WIDTH        # the annotation is optional everywhere

    count be count + 1             # assignment: `be` without `let`
    print(title)
    print(count)
    print(width)

Immutable is the default, and this is the first real cost of the language. In NumPy every name is rebindable and every array is mutable, and nothing asks which you meant. Here the compiler asks once, at the binding, and in exchange a reader of let title be … knows without searching the function that no line below changes it. The word is mutable and not mut because abbreviated keywords lose an argument the language still holds to: count the spelling across Fortran, MATLAB, R, Julia, Python, JavaScript and PHP before shortening a word — not across the corpus a model was trained on.

Assignment is a statement, not an expression. It has no rung on the precedence ladder and produces no value, so if (x be 1): is not something the grammar can express. There is also no compound assignment: count be count + 1 and never count += 1. One spelling instead of two, and a rebinding inside a loop stays visible on the line where it happens.

const is the one inherited abbreviation in the language, and the register of shortened keywords names it. It is a compile-time constant rather than a read-only binding: it is substituted where it is used, and it may stand as a const-generic argument.

Literals

def main():
    let decimal be 1_000_000
    let hex be 0xdead_beef
    let octal be 0o777
    let binary be 0b1010
    let sized be 42i32

    let pi be 3.14
    let tiny be 1e-9
    let single be 2.5f32

    let greeting be "hola"
    let escaped be "a\tb\nc \u{1F600}"
    let letter be 'a'
    let flag be true
    let nothing be ()

    let missing: Error? be null     # absence, and the only spelling for it
    print(missing?)

The escape list in full is \n \t \r \\ \" \' \0 \u{…} and nothing else. There are no block comments and no triple-quoted strings; # runs to the end of the line, and a run of ## immediately above a declaration is a doc comment — see Toolchain for what reads it and why it survives the lexer.

Numeric types are written out and never converted implicitly. I8 … I64, U8 … U64, F16, BF16, F32, F64, with Int aliasing I64 and Float aliasing F64. as is always written, including where it loses precision, because a language that silently widens an F32 to an F64 has made a decision about your memory budget that you did not ask for.

Four numeric behaviours are decided here rather than left open, because a numeric language cannot leave them open. Integer overflow panics in debug builds and wraps in release. Integer division truncates toward zero and % takes the sign of the dividend. as from float to integer saturates, and NaN becomes zero. And F32 and F64 implement Eq but not Ord, because NaN has no total order — so sorting floats takes an explicit total-order function rather than silently producing a permutation that depends on where the NaNs started. Reductions have a defined order unless they are marked unordered, and a result that differs between runs is opt-in, because this is a language whose users publish.

null is a literal like true and false: its spelling is fixed, so a program may not bind the name. It inhabits a nullable type T? and nothing else. () above is the empty tuple, which is a value and not an absence — a function with no return type returns it. changing

Types#

A record is a type. A sum type is a choice. Both take generic parameters with of, and a generic parameter may be a type or a constant. 

type Doc:
    title: String
    body: String

type Pair of (A, B):
    first: A
    second: B

choice Format:
    Plain
    Markdown
    Json

choice Tree of T:
    Leaf(T)
    Node(Box of (Tree of T), Box of (Tree of T))

def main():
    let doc be Doc(body: "named arguments, in any order", title: "Doc")
    print(doc.title)

A choice is a closed set of alternatives, and closing it is the point. A match over a Format must handle every variant, so adding Latex to the declaration breaks every place in the program that decided what to do with a format — loudly, at compile time, with the missing patterns listed. That is the opposite of a string constant or an integer flag, where adding a fourth value breaks nothing and is discovered by a wrong answer. It is also what lets a tool schema turn a choice into a JSON enum with nothing written by hand.

Box of T is a heap indirection, and it is why Tree can name itself. A recursive record with no indirection has no finite size, and Science asks you to write the box rather than inserting one, because where the indirection sits is a performance decision in a language whose users care about memory layout.

Generic arguments, and where the parentheses go

type Doc:
    title: String

def one(items: Array of Doc) -> Int:            # one argument needs no parentheses
    items.length()

def two(index: Map of (String, Int)) -> Int:    # two or more do
    index.length()

def nested(groups: Array of (Map of (String, Int))) -> Int:
    groups.length()

def build() -> Array of Doc:
    (Array of Doc).new()                        # an associated call needs its own parens

This is not a style rule; it is the grammar. Array of Doc parses because a single type argument cannot contain a top-level comma, so the next comma ends it. Map of String, Int in a parameter list genuinely cannot be parsed — that Int could be Map's second argument or the function's second parameter, and no amount of lookahead decides which, because both readings are well-formed. So several arguments take parentheses, and nesting follows the same rule for the same reason.

Array of Doc.new() is ambiguous in the same family: does .new() attach to Doc or to the whole generic type? Science requires (Array of Doc).new(). The alternative considered was making the space in Array of Doc .new() significant, which would make whitespace load-bearing in a way nothing else in the language is. The form is ugly and it is rare, and the compiler names it rather than producing a confusing downstream error: 

error[SC0116]: `.new()` could belong to `Doc` or to `Array of Doc`
 --> build.science:5:5
  |
5 |     Array of Doc.new()
  |     ^^^^^^^^^^^^^^^^ this associated function call is ambiguous
  |
  = note: Science reads it as `(Array of Doc).new()`, the whole generic type
  = help: write the parentheses to say so: `(Array of Doc)`

Const generics, and the arithmetic they admit

type Grid of (T, const ROWS: Int, const COLS: Int):
    cells: Array of T

type Padded of (T, const N: Int):
    cells: Array of T
    grown: Padded of (T, N + 1)
    shrunk: Padded of (T, N - 1)
    tripled: Padded of (T, N * 3)
    doubled: Padded of (T, 2 * N)
    halved: Padded of (T, N / 2)

Const generics are in the core because tensor shapes are built out of them. Tensor of (F32, (batch, 768)) carries 768 as a generic argument, and 768 is not a type. Retrofitting that later means reopening the parser, the resolver and every snapshot, so it is here in F0 even though tensors are not.

The arithmetic is linear by grammar, not by a check run afterwards. + and binary - take two const expressions; * and / require an integer literal on one side. So N * M for two parameters is not a program the parser can build a node for, and it is reported there: 

error[SC0157]: a const expression multiplies only by a literal
 --> grid.science:3:24
  |
3 |     bad: Grid of (T, N * M, M)
  |                        ^ one side of this needs an integer literal
  |
  = note: `const-expression-arithmetic.md` §2.1 keeps const arithmetic linear by grammar: two parameters may be added or subtracted, never multiplied or divided by each other

Why refuse the general case? Because type equality on Grid of (T, ROWS, COLS) is const equality, and four separate things have to agree about it — type equality, shape equality, index bounds, and the key that decides whether two monomorphisations are the same function. Four implementations of "are these two extents the same?" is four answers, and the fourth one is a linker emitting two symbols for one function. A linear form normalises to a canonical k + Σ cᵢ·aᵢ; structural equality on that form is sound and complete; and the normaliser never receives a non-linear input because the grammar admits none.

The cost is real and the design admits it. Rust's generic_const_exprs has been unstable since 2020, and it did not stall on normalising N + 1 against 1 + N — that part was understood early. It stalled on proving a const expression well-formed before the parameter is known, which needs a predicate language and an entailment checker. Science refuses that feature and pays for the refusal in post-monomorphisation errors: a library can ship a signature that breaks for your shape, and you meet the error inside code you did not write. The mitigation is that the diagnostic must name the instantiation, the parameter, the value and the call that produced it. If that chain is not rendered well, the decision is indefensible.

N / 2 divides by a literal and truncates toward zero, and equality over quotients is deliberately incomplete: N / 4 and (N / 2) / 2 denote the same function and the compiler cannot prove it, so it says cannot prove and prints both normal forms rather than guessing. The fold that would close that gap — (2N + 1) / 2 → N — is unsound at N = -1, and the const language carries no sign information about its parameters.

Closures have a type, and it has no keyword

def apply(f: (Int) -> Bool, x: Int) -> Bool:
    f(x)

# `->` is right-associative, and `?` binds tighter than `->`,
# so a nullable closure needs its own parentheses.
type Pipeline:
    step: ((Int) -> Bool)?
    stages: Array of ((Int) -> Bool)
    curried: (Int) -> (Int) -> Bool

def twice(f: (Int) -> Int, x: Int) -> Int where Int: Eq:
    f(f(x))

(A) -> B reads as takes an A, gives a B. It is what Kotlin and Swift write exactly, what TypeScript writes with =>, and what the ML family writes with the arrow alone. The earlier spelling was function(A) returns B, which read as a noun naming what the parameter is; once returns became -> and function became def, the mechanical carry-over def(A) -> B was left naming nothing — a declaration that lost its name. The bare arrow sidesteps the problem by having no word to be the wrong part of speech, and it puts no new word on the reserved list.

Three edge cases, all of which you will meet. It is right-associative, so (A) -> (B) -> C is (A) -> ((B) -> C), which is currying and the only useful reading. ? binds tighter than ->, so (A) -> B? is a closure returning a nullable and a nullable closure is ((A) -> B)?. And as a generic argument it needs its own parentheses — Array of ((Int) -> Bool), never Array of (Int) -> Bool — for exactly the reason Map of (String, Int) does.

The one thing that cannot be spelled. (T) collapses to T with no node of its own, so a one-parameter closure whose single parameter is a tuple has no spelling: ((A, B)) -> C parses as a two-parameter closure. This is a genuine hole, and it is closed by a convention rather than by grammar — pairs in Science are records, so the only tuples in F0 are the return shape of a fallible function, and none of those is passed as an argument. If that stops being true, the answer is a named record and not a third paren.

Functions#

def declares every function form there is. Generic parameters follow the name with of; bounds go inline or in a where clause, and several join with +. 

interface Summarize:
    def summarize(self) -> String
    def preview(self) -> String:
        self.summarize().truncate(80)

type Doc:
    title: String
    body: String

type Pair of (A, B):
    first: A
    second: B

def summarize_doc(doc: borrowed Doc) -> String:
    doc.body.truncate(200)

def duplicate of T: Clone + Eq(value: borrowed T) -> Pair of (T, T):
    Pair(first: value.clone(), second: value.clone())

def best_of of T(left: borrowed T, right: borrowed T) -> String
        where T: Summarize + Clone:
    if left.summarize().length() >= right.summarize().length():
        left.preview()
    else:
        right.preview()

def paired of (A, B)(first: A, second: B) -> (A, B):
    (first, second)

The last expression of a body is its value. return exists for leaving early and is not written at the end of a function. A function with no return type returns (). This is the ML and Rust convention rather than Python's, and it is one place the language expects a Python reader to look twice: there is no implicit None, and a body whose last line is a statement rather than an expression returns (), because that is what it produced.

Signatures are fully annotated; bodies are fully inferred. Inference is local and by unification, and interface bounds are checked after it. Global Hindley–Milner was rejected on two grounds: it does not hold up in the presence of interfaces and regions, and its errors point far from the fault — which, for a language whose diagnostics are the only teaching channel it has, is disqualifying. The practical consequence is that you write types at a boundary and nowhere inside one. It is also why tools --json can derive a schema without a type checker: the parameter types are already written down.

If you are arriving from Python: def is a borrowed word, and the language knows it

The word is the same and the declaration is not. def introduces every function form there is — a free function, a method inside a has block, a required or defaulted member of an interface — so there is no second spelling to learn. Parameters carry types, the return type follows ->, and there is no implicit receiver: self is a parameter you write, and writing it is what makes a function a method rather than an associated one.

It is worth knowing that the design note that introduced def argued against it and lost. The rule was that a keyword is a whole English word, and def is a word with four letters removed. The familiarity argument, examined, counted the spelling across the languages this audience actually writes — Fortran FUNCTION, MATLAB function, R function, Julia function, JavaScript function, PHP function, Python def — and came out six to one against, with the six including the three languages the project names as its competition. The conclusion in the note is that familiarity does not favour def: it favours Python, and Python is one dialect of the audience rather than the audience.

It was adopted anyway, by the owner's decision. What survived is not a veto but an obligation to record: a shortened keyword must beat that audience test, and if it is adopted without beating it, it is named in a register. The register has two entries, const and def. function is now an ordinary identifier — you may bind it, name a field with it, even write def function(…) — and writing it where a declaration belongs is a migration diagnostic rather than a stray-name error. 

error[SC0156]: the declaration is written `def`
 --> old.science:1:1
  |
1 | function old_style(x: Int) -> Int:
  | ^^^^^^^^ `function` is not a keyword in Science
  |
  = note: `def` declares every function, method and interface member
  = help: write the declaration as: `def`

That fix is machine-applicable, which is the property that matters most here. Science has no training corpus and will not have one for years, so for a model writing Science the diagnostics are not the fallback channel — they are the only channel. A loop that can apply a fix converges in one round trip; a loop that must infer the fix from prose sometimes does not converge at all. The same reasoning is why one mistake must cost one message: a human fixes the first of three cascaded errors, and a model attempts three fixes, two of which are wrong.

Interfaces#

An interface is a set of requirements a type can satisfy. It may carry required methods, default bodies that call them, and associated types. Implementations are statically resolved. 

type Doc:
    title: String
    body: String

type Position:
    line: U32
    column: U32

interface Summarize:
    def summarize(self) -> String

    # A default body may call any other method of the interface,
    # including one it does not itself provide.
    def preview(self) -> String:
        self.summarize().truncate(80)

Doc implements Summarize:
    def summarize(self) -> String:
        self.body.truncate(200)

Position implements Copy            # a marker: one line, no block

Doc implements Summarize reads in the order the sentence goes, which is the reverse of Rust's impl Summarize for Doc. A marker interface — one with no methods — is implemented on one line, because F0 has no empty block and inventing one for this case would be a grammar rule bought for a formatting preference.

The orphan rule applies: an implementation is legal only if the interface or the type belongs to the module declaring it. Without it, two libraries can each implement one interface for one type, both compile, and the program that uses both has two answers to one question with no way to say which it wanted.

Receivers, and what each one costs

type Doc:
    title: String
    body: String

Doc has:
    def summarize(self) -> String:          # shared borrow of the receiver
        self.body.truncate(200)

    def reset(mutable self):                # exclusive borrow
        self.body be String.new()

    def into_title(self: Self) -> String:   # consumes it
        self.title

    def new(title: String) -> Doc:          # no `self`: an associated function
        Doc(title: title, body: String.new())

def main():
    let doc be Doc.new("inferred, never written")
    print(doc.summarize())

The three receiver forms are the three things a method can do to the value it is called on, and they are not interchangeable. self reads it, and any number of readers may overlap. mutable self writes it and excludes every other borrow for as long as it is live. self: Self takes ownership, and the caller cannot use the value afterwards — which is what makes a builder's final build() or a handle's close() impossible to call twice.

A function with no self is an associated function, called through the type: Doc.new(…). It is how Science spells a constructor, and there is no special constructor syntax because a constructor is a function that returns the type, which the language can already say.

Associated types

interface Iterate:
    type Item
    def next(mutable self) -> Self.Item?

type Countdown:
    remaining: Int

Countdown implements Iterate:
    type Item is Int

    def next(mutable self) -> Self.Item?:
        if self.remaining <= 0:
            null
        else:
            self.remaining be self.remaining - 1
            self.remaining

Associated types are in F0 because without them Iterate cannot name its element type and no generic container interface can be written at all. An associated type belongs to the implementation rather than to the interface: a Countdown yields Ints and there is no second way to iterate a Countdown, which is exactly the difference between an associated type and a generic parameter.

An exhausted iterator returns null. Self.Item? is the nullable type; there is no wrapper to construct, so the present case is the value itself and the absent case is the literal. That is smaller than an Option, and it is also less: there is no map, no unwrap_or and no is_some, because there is no type left for those methods to hang off. changing

Operators are interfaces

type Vector2:
    x: F64
    y: F64

Vector2 implements Add:
    def add(self, other: Vector2) -> Vector2:
        Vector2(x: self.x + other.x, y: self.y + other.y)

Vector2 implements Eq:
    def eq(self, other: borrowed Vector2) -> Bool:
        self.x is other.x and self.y is other.y

def main():
    let sum be Vector2(x: 1.0, y: 2.0) + Vector2(x: 3.0, y: 4.0)
    print(sum.x is 4.0)

The full list is Add Sub Mul Div Rem Pow MatMul Neg Index Eq Ord Copy Clone Drop Iterate From Display. A scientific language in which + does not work on your own type is not a scientific language, so implementing an operator interface is how a user type joins in. Eq and Ord are what the comparisons dispatch to, and because there is exactly one spelling per comparison there is no second form for a parser rule to drift from.

Copy and Clone are the two that will catch you. Copy means assignment duplicates instead of moving, and it is for small values whose duplication is a register move. Clone means duplication is explicit and possibly expensive. A type that is neither — which is most types — moves when you assign it, and that is the subject of the next section.

Ownership and borrows#

Memory is managed at compile time. Every value has exactly one owner; assigning, passing or returning moves that ownership unless the type is Copy; leaving scope destroys the value. There is no garbage collector, no reference counting, and no lifetime annotations to write.

Why a scientific language wants this at all

Ownership is usually sold as memory safety, and for this audience that is the least interesting thing it buys. Four concrete reasons, none of them abstract:

Device memory. Garbage collectors and GPUs are enemies. A GC does not know about device memory pressure, so a program runs out of GPU memory while host memory is fine and the collector sees no reason to run. Julia's CUDA support carries that wound permanently. Ownership frees a device buffer at a program point the compiler can name.

In-place updates without aliasing bugs. NumPy's slicing returns views, and a view that aliases the array you are writing to produces a wrong answer with no error. Futhark invented uniqueness types solely so that a pure language could write x[i] = v in place and stay correct; ownership is the same guarantee with a better surface. Silent view aliasing becomes a compile error.

Random keys that cannot be reused. A splittable generator is neither Copy nor Clone, and splitting consumes it. Reusing a JAX key returns the same numbers, is valid Python, and is the best-known footgun in that library. Here it is use-after-move, SC0301, a compile error — and it falls out of ownership rather than being a feature anybody added. This is the one place Science is strictly stronger than the best existing design in the field.

No pauses, which matters for acquisition, control loops and MPI ranks, where a collector deciding to run is a missed deadline rather than a hiccup.

The cost is paid at the surface, and it will surprise every NumPy user exactly once: a large array assigned to a new name moves, and the old name is dead. Auto-borrow removes the most visible part of it; the diagnostics carry the rest. 

type Doc:
    title: String
    body: String

type View:
    source: borrowed Doc           # a record may hold a borrow; the region is inferred

def retitle(doc: mutable borrowed Doc, title: String):
    doc.title be title

def compare(left: borrowed Doc, right: borrowed Doc) -> Bool:
    left.title is right.title

def main():
    let mutable doc be Doc(title: "a", body: "")

    # A parameter declared `borrowed` is borrowed automatically, so the call
    # site is bare. The signature still carries the information.
    retitle(doc, "renamed")
    print(compare(doc, doc))

    # Write the borrow out where the position is not a call site.
    let view be View(source: borrowed doc)
    print(view.source.title)

The rules, in full, are six lines. Every value has one owner. Assigning, passing or returning moves it unless the type is Copy. Using a moved value is SC0301. A value may be borrowed shared any number of times, or exclusively once, never both at once. No borrow outlives its referent. Leaving scope destroys the value, running Drop if it has one. Everything else in this section is a consequence of those six.

Auto-borrow at call sites. If a parameter is declared borrowed T, the caller writes compare(a, b) and not compare(borrowed a, borrowed b). The signature still says borrowed, so a reader keeps the information; only the noise at the call site goes. Rust rejected this and Mojo adopted it, and for this audience Mojo is right — a scientist reading gemm(&a, &b, &mut c) is reading three sigils that tell them nothing they could not have read in the signature. An explicit borrow stays legal where it clarifies, and it is required where the position is not a call site, as in the View construction above.

What a region is, and why you never write one

A region is the set of program points at which a borrow is live. That is a control-flow property, not a lexical one: a borrow ends at its last use, not at the closing of a block. The compiler assigns a fresh region variable to every borrow and to every reference inside a type, collects outlives constraints from assignments, calls and returns, propagates them to a fixed point, and then checks for conflicts. It does this over a control-flow graph, which is why the compiler has a mid-level IR at all.

There are no elision rules, because elision is not the mechanism. Rust's lifetime elision is a convenience over a syntax that remains available when the guess is wrong; Science has no syntax to fall back on, so a function's parameter and return regions are simply an analysis result. Functions are analysed in reverse topological order of the call graph, and mutual recursion is resolved by a fixed point over each strongly connected component. Once you are willing to read the body, guessing from the signature is strictly worse than reading it.

A type gets one region variable per borrowed field, and the relation between them is inferred at each use site rather than declared once. Where Rust writes FftwPlan<'a> and puts 'a on both fields — asserting the two outlive the same thing — Science asserts nothing, and each construction generates its own constraints. That keeps information Rust's single name discards. It costs two things: a type's region stops being a property of the type and becomes a property of each value, and the intersection of two field regions can be empty, which means a value that is dead at birth and needs its own diagnostic rather than a generic conflict.

What happens when inference has no single answer. Rust reports an error and makes you write 'a. Science cannot make you write anything, so it refuses the program: SC0340, with the offered fix being to return an owned value or an index instead. That is uncomfortable — it rejects a program for being ambiguous rather than wrong — and it is the honest consequence of removing the syntax. The mitigating fact is that the ambiguous signatures are overwhelmingly ones that should return an owned value anyway: a symbol-table lookup that hands back a borrow is usually wrong, because the caller almost always goes on to mutate the table. If SC0340 fires often in real code, the no-syntax decision is wrong, and the design says so rather than assuming otherwise.

One thing the claim does not say, and should not be read as saying. Region inference is interprocedural within a crate. Across a crate boundary the inferred relation — for each return region, which parameter regions constrain it — is serialised into crate metadata, because otherwise a module could not be checked without its dependencies' bodies. That summary carries exactly the same information a lifetime annotation does. The claim is that a programmer never writes a region. It was never that the compiler does not need one.

What a borrow error will look like. With no 'a to print, a message has no choice but to describe the program, which is a constraint worth accepting on purpose: the error is forced to be a narrative because it cannot be algebra. Three spans — where the borrow was born, what keeps it alive, where the conflict is. The "still needed here" span is the load-bearing one, and it is the one a solver that merged its constraints for speed can never produce, which is why provenance on every constraint is a decision taken now rather than later. not implemented

interface Summarize:

The two functions do the same thing by different means, and the difference is worth knowing. describe_each is generic and monomorphised: the compiler emits one copy per concrete T, each specialised, each inlinable, and the binary grows. describe_any takes any Summarize, which is one function in the binary dispatching through a table at run time. any Interface is always used behind an indirection — a borrow or a box — because its size is not known at the call site. Monomorphisation is the default because numeric specialisation is where this language's performance is supposed to come from.

Control flow#

if/else is an expression. A block is an indented body after :, or a single expression written inline. There are exactly two loops. 

# The inline body ends where the EXPRESSION ends, not at the newline: the
# then-branch stops at `else`, because `else` cannot continue an expression.
def preview(text: borrowed String, limit: Int) -> String?:
    if text.is_empty(): null else: text.truncate(limit)

def count_to(width: Int, n: Int) -> Int:
    let mutable total be 0

    for i in 0..width:             # half-open: the last value is `width - 1`
        print(i)

    for i in 0..=n:                # inclusive: it visits `n`
        total be total + i

    total

def refine_until_stable(start: State) -> State:
    let mutable state be start

    # `loop` is the only unbounded loop, and `break` is the only way out.
    # There is no `while`.
    loop:
        if converged(state):
            break
        state be refine(state)

    state

type State:
    residual: F64

def converged(state: borrowed State) -> Bool:
    state.residual <= 1.0e-6

def refine(state: State) -> State:
    State(residual: state.residual / 2.0)

The inline body rule is about expressions, not about lines. In if a: b else: c the then-branch stops at else because else cannot continue an expression — fitting on one line is a consequence of that rule, not the rule. An inline body may be an expression, an assignment, or return / break / continue. It may not be a let, which would bind a name nothing could then use; that is SC0109. A dangling else binds to the innermost if.

while is not in the language. A condition-driven loop is loop: with an early break, which is two lines longer. That is Go's trade and its known cost, taken for a specific reason: ranges already cover the counting case while is usually misused for, and the language would otherwise carry two forms where one does. loop while condition: was considered and held back, because it reintroduces exactly the second form this decision exists to remove — and it is source-compatible to add later if the verbosity is genuinely felt.

Ranges use .., never :. 0..n is half-open and 0..=n is inclusive, so for i in 0..n: is the counting loop and there is no off-by-one to memorise. The colon is not available for a slicing notation because : already opens blocks and separates match arms, fields, named arguments and bounds, and a character with five jobs cannot take a sixth. Ranges sit below everything on the precedence ladder, so 0..n - 1 counts to n - 1.

for x in xs: borrows. It is the same construct as xs.iterate(), so iterating a collection does not consume it, and consuming is written out with iterate_consuming(). This is a deliberate correction of the single most-reported wart in Rust's collection API, where for x in v silently moves and burns every beginner once.

Exhaustiveness is the whole reason choice exists. A wildcard _ arm switches it off, and that is the trade: use a wildcard where the cases are genuinely open-ended (an integer, a character) and name every variant where they are not. The difference shows up the day somebody adds a variant — a wildcard absorbs it silently, and a complete set of arms stops the build in every place that has to decide what to do about it. That is the property the concrete error form is buying.

A variant may be written qualified or bare: Plain and Format.Plain are the same pattern. The bare form is what a match arm usually wants, since the scrutinee's type already says which choice is meant; the qualified form is there for when two choices in scope have a variant with the same name.

Record patterns match by field name, and _ inside one means this field, whatever it is. Note that Point(x: x, y: _) binds x and ignores y: the name left of the colon is the field and the thing right of it is the pattern, which is the same order construction uses.

Exhaustiveness is a type-checker job, and the type checker is not wired in, so a non-exhaustive match parses and resolves cleanly today. The diagnostic is specified, it takes a code in the SC0250 range, and it is not built. changing

Errors changing#

A function that can fail returns its value and an error, and the error type is nullable. There is no Result, no Option, no try and no exception.

The three pieces, and what each one is

T? is a nullable type — a T, or null. It replaces Option of T, and it is the spelling Kotlin, Swift, TypeScript and C# all share, so it needs no teaching. There is no wrapper: the present case is the value, which is why return text.truncate(60) can satisfy a -> String? and why an exhausted iterator just returns null.

-> (Config, Error?) is a pair, received by destructuring at the binding: let config, err be read_config(path). A function with nothing to hand back returns the error alone, because the pair would have () in its first slot and a name bound to that could do nothing.

? is a presence test and it is total. This is the piece most likely to be misread. It looks like Rust's propagation operator and it is not it: err? is a Bool, true when the value is not null. It never returns from the enclosing function, never unwraps and never fails. print(pending?) prints false or true. The character was free because the earlier design removed the propagation operator, so it now means exactly one thing.

Where ? binds was an open question on this page, and the implementation has settled it: ? sits on the tightest rung, with call, index and field access, and applies to the whole postfix chain to its left. config.port? is (config.port)? and next()? is (next())?. It reads in the opposite direction from the prefix try it replaced, which covered the chain that followed it — which is why this was a rewrite of that rung and not a rename. The second half of the old question does not arise: Foo? the type and Foo? the test are different grammar positions, and no production admits both.

Which error type to name, and what each one costs

type Config:
    host: String

Config has:
    def empty() -> Config:
        Config(host: String.new())

    NotFound(String)
    Malformed(String, Int)

    def message(self) -> String:
        "the configuration could not be read"

type StartupError:
    detail: String

StartupError implements Error:
    def message(self) -> String:
        "the program could not start"

StartupError has:
    # The conversion the removed `try` used to perform invisibly. It is an
    # ordinary associated function now, and the caller writes the call.
    def from_config(inner: borrowed ConfigError) -> StartupError:
        StartupError(detail: inner.message())

def read_concrete(path: borrowed String) -> (Config, ConfigError?):
    (Config.empty(), null)

# `Error?` is shorthand for `(any Error)?`: it composes across a library
# boundary, and it boxes, which the concrete form does not.
def start(path: borrowed String) -> (Config, Error?):
    let config, err be read_concrete(path)
    if err?:
        return (Config.empty(), StartupError.from_config(err))
    (config, null)

# A function with nothing to hand back returns the error alone.
def save(path: borrowed String, text: borrowed String) -> Error?:
    let err be write_file(path, text)
    if err?:
        return StartupError(detail: "the file could not be written")
    null

Error is a one-method interface — def message(self) -> String — so Error? in a return position is shorthand for (any Error)?. The shorthand exists because the long form appears in the signature of every fallible function in the language, and -> (Config, (any Error)?) is not a signature anyone should have to read.

The choice between the two forms is real and it is the author's. A concrete error type — usually a choice — keeps match exhaustive and costs no allocation, so it is right when the caller is expected to tell the cases apart. The interface form composes across a library boundary and boxes, so it is right at the top of a program where the only question is what to print. The rule of thumb: a library exports a concrete type, an application uses Error?.

Conversion between error types is written out, at the return. There is no implicit widening — which is exactly what the removed try did invisibly by calling From, and no section of the old design ever said that it did, which is how two files in the example corpus came to depend on an unspecified conversion. Making it explicit closes that hole by construction, and the price is visible above: StartupError.from_config(err) is a call you write.

What this costs, stated plainly

Three lines per fallible call instead of one. The call, the if err?:, and the return. This is Go's well-known tax and it is real: when the corpus file for this feature was rewritten against the new model it roughly doubled in length. The argument for paying it is that the error path is then written where it happens, in the order it happens, for a reader rather than for a writer — and the premise of the whole design is that this code is mostly read.

Nothing in a type forces the error to be read, and that is the serious one. A Result made ignoring a failure a type error; a returned Error? can be dropped on the floor, which is Go's problem and Go pays for it. The mitigation is SC0140: a binding of a nullable error type that is never tested with ? before the function returns is a compile error, not a lint. It is a use-before-check analysis, it is cheap, and the design says it must ship with the model or the model lands worse than what it replaced. It has not shipped.

And one place the new model is straightforwardly worse. Two fallible steps inside a single method chain produce two error types, and the conversion has been relocated to the caller's return — but a chain has no return. The old model's try converted through From at exactly that point. There is no mechanism to point at yet, and the design note says so rather than writing it up as anything else.

Chains and closures#

A pipeline is mostly glue: load, reshape, filter, batch, hand to a model, collect, write. The arithmetic in the middle is somebody else's library; the part you write is the part between the libraries, and it is a chain of method calls.

    def summarize(self) -> String

    title: String
    body: String

    def summarize(self) -> String:

    docs

Adapters are lazy; terminals are eager; there is no eager mode. docs.iterate().map(each.title) allocates nothing and touches nothing until a terminal pulls it, which is why it is legal over a forty-gigabyte file. Six adapters over a million rows allocate six million-element arrays eagerly and none lazily, and take(5) after a map does five units of work lazily and a million eagerly. Three adapters are barriers and buffer the whole stream — sorted(), sorted(by:) and reverse() — which is why putting a .sorted(…) before a .discard(…) sorts rows you are about to throw away. That is the one performance trap laziness leaves open, and it is a documentation problem rather than a language one.

Two closure forms, and the one case that needs the second

each names the subject of the enclosing call without declaring it. It is the shorter form and the one most chains want. It is not a loop word — iteration is for x in xs, and naming a closure's subject is the only thing each does, which is why it is reserved: letting a program shadow it would make every chain ambiguous.

name giving expression declares the parameter. It is required when the parameter is used more than once, and for the one case each cannot express: nesting. In outer.map(each.inner.map(each.x)) the two each refer to different subjects and the inner one shadows the outer irrecoverably. Science rejects that rather than picking a rule: 

error[SC0115]: a nested `each` would name a different subject than the `each` around it
 --> chain.science:2:29
  |
2 |     docs.map(each.inner.map(each.x))
  |                             ^^^^ this `each` is inside another `each`
  |
  = note: name the parameter instead, with the `giving` form: `outer.map(item giving item.inner.map(each.x))`

Two each in the same argument are fine — they are the same subject — so only an enclosing each is an error. Having two spellings for one idea is design debt, and it is recorded as deliberate: Kotlin and Swift carry the same debt and it has not hurt them.

There is deliberately no lambda. lambda x: x > 5 is fifteen characters, x giving x > 5 is fourteen, and each > 5 is eight — so it would be a third spelling, longer than both spellings it joined, of something the language already says two ways. But the decisive argument is not length. λ is a primary named quantity in five fields — wavelength in spectroscopy, the decay constant in kinetics, an eigenvalue in linear algebra, the rate of a Poisson process, the ridge or lasso penalty in machine learning — and in every one of them it lands in binding or parameter position, which is exactly where a reserved word cannot be worked around. let lambda be 532 and def ridge(x: Matrix, lambda: F64) have to keep compiling, and they do.

Closure bodies are a single expression. There is no multi-statement closure and no block form, which is a real limit and a deliberate one: a lambda x: followed by a newline is, in shape, a block-opening :, and the indentation grammar cannot afford a construct where : means something else. Multi-parameter closures — (acc, x) giving acc + x — are designed and not implemented: the closure node carries one optional parameter today, so reduce and accumulate cannot yet be written. changing

What ownership does to a chain

A chain value is a borrow of its source, wearing a long type. iterate() takes a shared borrow and each adapter moves that borrow forward into itself, so let titles be docs.iterate().map(each.title) leaves titles borrowing docs, and pushing to docs before the chain is consumed is a borrow error. Put the other way round: a chain freezes its collection for its whole life, so "mutate while iterating" is a compile error rather than a rule in the manual. That is the most valuable thing ownership buys this API.

Because regions are flow-based rather than lexical, running the terminal before the mutation is not an error at all — the borrow ends at its last use. Had the language chosen lexical lifetimes, stored chains would be close to unusable. A chain is also neither Copy nor Clone and terminals take it by value, so a half-consumed chain cannot be silently observed twice.

Items that were borrowed stay borrowed all the way into collect(), and the printed type tells you: Array of borrowed Doc is a set of views into something else, Array of Doc is yours. The rule that makes this bearable is the copy-out rule — a place expression returned from a closure yields the value when its type is Copy and a borrow otherwise — so .map(each.weight) on an F32 field gives F32 and .map(each.title) on a String field gives borrowed String. The escape is one link: .owned().

In F0 a chain cannot cross a function boundary. Writing -> MapOver of (Keep of (ArrayIterate of Doc, …), …) in a signature is not a language anyone should ship, so a function returns a collection and materialises with .collect(). That costs one allocation per boundary, and the boundary is where a pipeline wants something concrete anyway: what you hand to the next stage is a dataset, not a recipe. Libraries return named source types; user functions return collections.

Calls always take parentheses, including when they take no arguments: text.length(), never text.length. The parenthesis-free form reads better in a chain and was considered; once functions are values, doc.summary is ambiguous between calling it and naming it, and a language cannot resolve that by guessing. Parentheses mean call; their absence means a field.

None of the method names above is implemented. There is no Iterate interface in a standard library, no iterate(), no keep or discard, no Set. The samples parse and resolve because each, giving and method-call syntax are real; the methods they name are design. changing

Foreign code#

Essentially every floating-point operation that matters in scientific computing already lives in a C or Fortran library somebody else tuned. dgemm is thirty years of hand-written assembly per microarchitecture. A language that cannot call these is not a scientific language, whatever its type system can prove.

The design goal is one sentence: make the boundary narrow, explicit and checkable on the Science side, and be honest that the C side cannot be checked at all. A declaration records a claim; the compiler verifies the half of the claim that lives in Science; unsafe marks the half that does not; and a hand-written safe wrapper is where the unverifiable half is discharged by an argument a human wrote down.

Five item forms, and each earned its place against a real library. def declares an undefined symbol resolved at link. type … is … spells a C typedef. const … be … as … transcribes a #define or an enumerator. static names an exported data symbol: HDF5's H5T_NATIVE_DOUBLE is not a constant — the header defines it as (H5open(), H5T_NATIVE_DOUBLE_g) — and CPython has 199 such globals. union is an opaque blob of a known size and alignment, which is the normal path for a C union rather than an unpleasantness that does not arise. symbol decouples the Science name from the linker name.

symbol exists because of the worst FFI bug in scientific computing. BLAS and LAPACK ship in two incompatible builds — 32-bit integers and ILP64 — with identical function names, identical argument counts and identical semantics, differing only in the width of eight of dgemm's thirteen arguments. Link the wrong pair and the result is not a crash: it is correct answers for small matrices and silently wrong answers for large ones. The ILP64 builds that matter ship distinct symbols, so naming them separately turns a wrong answer at run time into an undefined symbol at link time. Where a vendor ships ILP64 under the same names — Intel MKL does — nothing can detect the mismatch, and the binding has to say so in a comment, because that is the only warning available.

kind static forces static linking; dynamic is the default, and the reason is specific to this audience: cluster module systems work by swapping the shared object under a fixed name, so statically linking OpenBLAS defeats the mechanism the cluster administrator is relying on.

when available changes how the whole block is lowered: instead of direct declarations the compiler emits a lazily initialised table of function pointers populated on first use, and every call becomes an indirect call through it. The block gains an is_available(). The cost is one load, one branch and one indirect call per foreign call — noise against a dgemm, not noise against a per-element function, which is why it is opt-in rather than the default.

The last comment in that block is a fact, not a stylistic note. An extern block does not open a namespace: its items land in the enclosing module, so declaring BlasInt twice in one file is SC0201, "defined more than once". Two integer widths for one library means two modules.

Why the block is unsafe at all. An extern declaration is a claim about code the compiler will never see: that a symbol of this name exists, that it takes these arguments in this order with these widths, that it does not retain the pointers it is given, that it does not free them. None of that is checkable. Writing the declaration is therefore itself the unsafe act, and the keyword belongs where the act is. Rust reached the same conclusion in its 2024 edition after a decade of extern blocks that looked safe.

What unsafe does not suspend is the part worth reading, because it is the part users of other languages assume is suspended. Type checking, trait resolution, ownership, borrow checking, region inference, overflow checks, bounds checks and exhaustiveness all still apply. unsafe means one narrow thing: the compiler's model of memory it can see is intact, and what you are about to do involves memory it cannot see. If an unsafe block is long, the binding is written wrong.

Named arguments are permitted at a foreign call site, and nowhere else in the language outside record construction. The reason is domain-specific and decisive: cblas_dgemm takes thirteen arguments, two of which are transposition flags that look identical, and confusing them produces a wrong answer rather than an error. This is the call every numerical Science program makes, and it has to be readable by someone checking a formula against a paper. Two call conventions in one language is design debt, and it is recorded as deliberate.

ffi.Span of T is a pointer and a length. At the ABI only the pointer crosses; the length exists on the Science side alone, for one reason — so that the wrapper's precondition, that lda * n does not exceed the buffer, is an expression the compiler type-checks rather than a comment. It is the raw material for a check, not the check itself.

The aliasing rule BLAS states in its own documentation — "C must not overlap A or B" — turns out to be the rule the borrow checker already enforces. A wrapper taking two shared borrows and one exclusive one makes gemm(a, b, a) a borrow error, caught by machinery that exists for reasons unrelated to FFI. Likewise a handle type with a Drop implementation: C's "call the destructor exactly once" is Science's ownership, so a cudnnHandle_t wrapped as a handle is destroyed exactly once, on every path out including early returns, at a program point the compiler can name. There is no goto cleanup and no way to forget one.

What cannot be checked, as a list

Written as a list so that a reader can see whether their problem is on it. Retention — that the callee does not keep a borrowed pointer past the call — is unstatable and unverifiable, and the borrowed keyword in an extern declaration is the assertion. Bounds — that m, n, k, lda are consistent with the buffer — is the single largest unverified surface in the design. Internal aliasing, because noalias is emitted on the strength of the declaration. Signature agreement with the real header. Reentrancy through C. setjmp/longjmp across Science frames, which skips every destructor and is undetectable. A library calling exit. Bitfields and variadics.

And the largest practical risk, which is about linking: the linker checks that a symbol exists and nothing else. C object files carry no type information, so a wrong argument count, integer width or struct layout links cleanly and corrupts the stack at run time. The first implementation therefore refuses by-value aggregate arguments entirely (SC0429) and requires pointer-to-aggregate, because BLAS, LAPACK, HDF5, cuDNN and MPI pass aggregates by pointer anyway — a restriction that can be lifted source-compatibly later. F16 and BF16 may not cross by value (SC0431) because C has no agreed by-value ABI for half precision: _Float16 is passed differently by GCC, Clang and MSVC. That wart is felt exactly where it hurts most, in mixed-precision training, and the alternative is an ABI that is right on one compiler and silently wrong on another.

Fortran is declared "C". Its difference is not the calling convention but the argument passing, which is expressed in the types, and the trailing-underscore symbols are handled by symbol "dgemm_". There is a genuine prize there: Fortran declarations carry INTENT(IN), INTENT(OUT) and INTENT(INOUT), which is precisely the borrowed / out-parameter / mutable borrowed distinction C headers lack, and LAPACK's doc comments state each array argument's dimension in a fixed machine-parseable format for 1,700 routines. That is the span length, in the source, for 1,700 routines — available only because somebody wrote the annotations down thirty years ago.

Tools and schemas#

tool declares a callable exposed to a model. It is a second function-declaration form, and it exists because it carries obligations a def does not — every one of which a compiler can check. 

choice LineShape:
    Gaussian
    Lorentzian
    PseudoVoigt

type Peak:
    centre: F64
    width: F64

## Fit Bragg peaks in a window of flight time.
##
## Uses the run's own dark-current subtraction. Fails if the window holds
## fewer than 32 channels, because the fit is then underdetermined.
tool fit_peaks(
        ## The run identifier, as printed in the run log.
        run: String,
        ## Lower edge of the window, in seconds from the pulse.
        window_lower: F64,
        ## Line shape to fit. PseudoVoigt is the usual choice.
        line_shape: LineShape,
        ## At most 32; the fit is underdetermined above that.
        max_peaks: U8) -> Int:
    0

## Expose the same computation to a human caller.
def helper(run: borrowed String) -> Int:
    run.length()

The thesis is that the schema is the signature. Every other way of exposing a function to a model writes it twice — once as a handler the compiler checks and once as a JSON Schema nothing checks — and the two copies sit next to each other inviting a reader to believe they agree. When they drift, the failure is invisible: the schema says a parameter is a string, the handler indexes it as a list, and the model is told something false about a function it is deciding whether to call. Here there is no second artefact and therefore nothing to drift from.

Why a keyword rather than a marker. A marker that changes nothing is an attribute, and a language should not spend a word on an attribute. tool earns one because it has five obligations def has not, and a compiler checks every one: every parameter type must survive a round trip through JSON Schema; it may not be generic; no parameter may be borrowed; it must carry a ## description; and its return type is constrained. Two more come from where it may stand — module level only, and never with a self receiver.

Each of those is an argument rather than a rule. Not generic, because the list a caller is given is flat and concrete with one schema per entry, so there is nothing for T to be instantiated at. Not borrowed, because there is no caller to borrow from: the arguments were built from what arrived a moment ago and the tool is the only owner there is. Not a method, because a tool is called by name alone and there is nothing for self to be bound to.

The description is mandatory, and only here

A tool with no ## run above it is SC0190, an error, and one whose summary line is blank is SC0195. This is the only construct in Science for which documentation is mandatory, and the justification is deliberately narrow, or it becomes "document your code", which a compiler has no business enforcing. Everywhere else a doc comment is read by somebody who has already decided to call the function. Here it is read by the caller in order to decide, so the string is an argument rather than prose — and the failure it prevents is invisible: an undescribed tool does not fail, it is simply never chosen, and no test catches that.

Three things in it were derived and not written. max_peaks: U8 alone produced "minimum": 0, "maximum": 255 — the bounds are the type's width, and no other tool SDK's int can say this. A choice whose variants carry no payload became a string enum, which is the largest single win in the mapping: the model gets the complete list and does not guess, the body matches on it exhaustively, and adding a fourth line shape updates the schema in the same edit, because they are the same declaration. And the ## run became description, because a doc comment is trivia to the lexer but is carried on the token it documents rather than discarded.

The mapping's honest edges. U64 gets a minimum and no maximum, because 264−1 is not exactly representable as a JSON number and emitting it would be a lie about what the other side can send. F32 and F64 both become {"type":"number"}, so the wire is wider than the type. A T? parameter is its payload's schema with the name left out of required, because JSON's "absent" and "present and null" are two states Science has one of, and the language does not pretend otherwise. NaN and the infinities cannot be written in JSON at all, so a tool taking an F64 takes a finite one and the schema cannot say so; no mitigation is proposed, and it is recorded as a limit of JSON rather than of Science.

A type the pass cannot map is reported as a gap rather than an error — the property is emitted empty, the name is dropped from required, and an "x-science-unmapped" array names it — because deciding that a type is wrong rather than unmapped needs the type checker, and the diagnostics that would do that (SC0504–SC0518) belong to a phase that does not exist. --all-functions runs the same walk over every top-level function; it is a measurement of the type mapping and deliberately not a default, because a file's functions are not a list of callables until somebody has said which ones are.

prompt and agent stay reserved and unspent, and using either in declaration position is SC0196 rather than the generic "reserved for a later phase" — a phrase that reads, to anyone who knows what a compiler phase is, as though a later pass will accept it. prompt fails the test tool passes: prompt arguments in the protocol this targets are not schematised at all — a flat list of name, description and a required flag, with no types — so a prompt declaration would have no schema to derive and no drift to prevent, which leaves a function that returns a list of messages, which is a function.

fmt writes to stdout unless --write is given, and it refuses any file that does not already lex and parse. That refusal is the whole safety property: reformatting a file whose token stream is a guess is how a formatter eats a program.

The formatter is why one spelling per operation matters. The earlier design carried both a word form and a symbol form for all six comparisons and called the duplication debt worth taking. It was not: a formatter cannot canonicalise between a == b and a is b, because the choice depends on the operands' types, and a formatter that must run after type checking is not a formatter. The two spellings were permanently un-normalisable, which for a language whose code is largely machine-written means permanent drift. One spelling each cannot drift, and removing the second form took five words off the reserved list as well.

Doc comments, and why they survive the lexer

A run of ## immediately above a declaration is a doc comment. Unlike an ordinary # comment it is carried on the token it documents rather than discarded, so it survives into the syntax tree and onward to anything that reads a signature — which is how tools --json produces a description nobody wrote twice. This has to happen in F0 and it cannot be retrofitted: once the lexer discards them, every tool downstream is built assuming they are gone.

The composition with ordinary comments is the part a docstring form cannot manage. # TODO next to a doc comment is an ordinary comment and does not become documentation. And a docstring would only ever cover functions: a record field, a choice variant, a const, a type alias and a module all want documenting and none of them has a body to put a string in. A docstring in a compiled language would also be an expression statement with no effect that the compiler silently treats as metadata, which is the one thing the language refuses to do anywhere else — resolve an ambiguity by guessing.

Blocks and line continuation

type Doc:
    title: String

def names_of(docs: borrowed Array of Doc) -> Array of String:
    # A line continues when the next line begins with `.`,
    # which is how a chain is broken.
    docs
        .iterate()
        .map(each.title)
        .collect()

# ...and when it begins with `where`, before a signature's bounds.
def largest of T(items: borrowed Array of T) -> (borrowed T)?
        where T: Ord:
    items.get(0)

# A line ending inside an unclosed bracket continues too, which is what
# makes an argument list breakable.
def widest(
    docs: borrowed Array of Doc,
    limit: Int,
) -> Int:
    limit

. and where are the whole list, and it is meant to stay that way. A line break is otherwise the end of a statement, and a reader should not have to look ahead to know whether it was. Inside unclosed parentheses or brackets, newlines and indentation are ignored entirely, which is the third case and the one every language has.

Blocks are delimited by indentation, spaces only. A tab in the indentation is SC0003 with no attempt to interpret it. Blank and comment-only lines take no part. Indentation matching no open level is SC0004. Comments run from # to end of line; there are no block comments. Trailing commas are allowed in every bracketed and parenthesised list.

Reserved words

    Held for later phases — using one is an error

      Deliberately not reserved

        The first list is the lexer's, word for word. Reserving costs nothing now and breaks every program using the name later, which is the whole argument for a list this long — but the second list has a known price and this audience pays it. shape, model and tensor are reserved globally, so x.shape and let model be … do not compile. That was accepted deliberately, so that the tensor and agent phases are guaranteed their syntax; the alternative considered was making them contextual keywords recognised only in declaration position. You will meet it the first time you try to name a parameter shape.

        The third list is free on purpose: grad, dim, dims, axis, device, dtype, unit and alias are each a common variable name in the code of the people this language is for, and that outranks the convenience of reserving them. Note that where is reserved, so you cannot define a function of that name, which NumPy users will reach for.

        Two words moved recently, and both moved into the first list. function left every list and is now an ordinary identifier — a program may bind it, name a field function, or write def function(…) — because the parser recognises the old declaration positionally, and a contextual test costs one line of lookahead where a reservation would cost an identifier the audience uses. tool went the other way, from "reserved for later" to a declaration keyword, because it now checks five things a def does not; a marker that changed nothing would have stayed a reservation. A word the language removed is still recognised where it used to stand and reported as a migration rather than as a stray name: SC0156 for function, carrying def as an applicable fix, and SC0155 for try, carrying none on purpose.
